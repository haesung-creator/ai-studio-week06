## 1. AI 사용 내역 및 과정 통제 기록

### 과제 1: 프롬프트 3기법 비교 분석 리포트
* **요청 프롬프트**: 고객 리뷰 분류 및 긴급도(1~3) 판정을 위한 Zero-shot, Few-shot, CoT 프롬프트 템플릿과 비교 분석 표 프레임워크 작성 요청
* **AI 생성 답변**: 3가지 기법별 프롬프트 구조, JSON 스펙 지시문, 비교 분석 표 양식 제시
* **채택 및 수정**: AI가 제시한 템플릿을 채택하되, CoT 기법 출력 시 JSON만 단독으로 추출할 수 있도록 후처리 정규식 요구 지시문을 보완함. 애매한 사례(#4, #5)의 정답 범주를 복수 경계 카테고리(`배송 | 서비스`, `가격 | 품질`)로 수정 반영.
* **검증 결과**: 챗봇 UI에서 총 21회 독립 실행 후 정해진 출력 스펙 준수 여부를 교차 검증하고 캡처 저장 완료.

### 과제 2: Mock 분류기 확장 파이프라인
* **요청 프롬프트**: 20% 확률 불량 응답 생성 모듈(`mock_llm.py`) 및 방어 파싱 로직(`classify.py`, `run_pipeline.py`) 구현 요청
* **AI 생성 답변**: `random.random() < 0.20` 기반 변형 문자열 생성 코드 및 `try-except` 파싱 코드 제시
* **채택 및 수정**: AI 생성 코드의 파이썬 스코프/들여쓰기 오류(`SyntaxError`, `NameError`), CSV 열 이름 불일치(`KeyError: 'review'`), 경로 오류(`FileNotFoundError`)를 직접 코드 리딩 및 디버깅하여 수정 반영함.
* **검증 결과**: `reviews_sample.csv` 200건을 대상으로 실행하여 파이프라인 중단 없이 `처리 200건 / 실패 27건` 형태로 실행 결과를 성공적으로 검증함.

## 2. 사용자 입력 검증 및 출력 검증 적용

### 사용자 입력 검증 (Input Validation)
* **적용 위치**: `run_pipeline.py`
* **검증 로직**:
  * 외부 CSV 파일 로드 시 `review_text`, `review`, `text` 등 다형성 열(Column) 이름을 자동 탐색하여 유효한 데이터를 추출함.
  * 입력 데이터 타입을 `str()`로 강제 변환하여 비어 있거나 형식이 맞지 않는 입력값으로 인한 런타임 오류 발생을 사전에 방지함.

### 출력 검증 및 방어 파싱 (Output Validation)
* **적용 위치**: `classify.py`
* **검증 로직**:
  * **1차 검증 (문자열 정제)**: LLM 출력값 내 코드펜스(` ```json ... ``` `) 포함 여부를 검사하고 정규식(`re.sub`)으로 정제하여 유효한 JSON 문자열로 복구함.
  * **2차 검증 (예외 처리 방어)**: `try-except (json.JSONDecodeError, TypeError)` 구문을 적용하여 문법이 파괴된 응답(사족형, 잘린 JSON) 수신 시 시스템이 다운되지 않고 안전하게 `None`을 반환하도록 통제함.
  * **3차 검증 (결과 집계)**: 파이프라인 집계 루프에서 `None` 반환 건을 `failure_count`로 누적하여 최종 처리 결과(`처리 N건 / 실패 M건`)를 정확히 산출함.
